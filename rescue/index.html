What I Actually Fix

The same four failures, every time

Tap through — this is what shows up in almost every AI-builder audit I run.

Found
GET /api/user/482/invoices
→ 200 OK, no session check
Any signed-in user can read any other
user's invoices by changing the ID.
Fixed
GET /api/user/482/invoices
→ 403, row-level policy enforced
Session is checked against the row owner
before a single record is returned.
Found
// bundled into the client JS
const STRIPE_KEY = "sk_live_51H..."
Full secret key, visible to anyone who
opens devtools on the live site.
Fixed
// server-side only
STRIPE_KEY = process.env.STRIPE_KEY
Client never sees it. Rotated the moment
the audit finds it exposed.
Found
SELECT * FROM orders
→ full table scan, no index
Fine at 40 rows in testing. Times out
once real customers start using it.
Fixed
SELECT * FROM orders WHERE user_id = $1
→ indexed, paginated, cached
Same query, handles real traffic
without falling over.
Found
Add a "refund" button
→ breaks the checkout flow
Every new feature request touches
generated code nobody can safely edit.
Fixed
Add a "refund" button
→ ships in an afternoon
Clean structure means new features
don't fight the old ones.
